## vLLM native DP+EP — how (learned this session, in the README)

- Offline `LLM(data_parallel_size>1)` is **hard-blocked single-process**. Native DP+EP
  only via the **online server**: `vllm serve <model> -tp 1 -dp 8 --enable-expert-parallel`.
  `ep_size` is *derived* = `DP×TP`; `--enable-expert-parallel` is a **bool, not a number**.
- **Startup gotcha:** DP=8 trips `OpenBLAS … pthread_create: Resource temporarily
  unavailable` (~17 procs × 80 BLAS threads). Fix: cap
  `OMP/OPENBLAS/MKL/NUMEXPR_NUM_THREADS=4` (+`TOKENIZERS_PARALLELISM=false`) in launch env.
- **Client must be async + concurrency-matched:** `gsm8k_serve_dp.py` uses aiohttp
  (one event loop) and `CONC=1319` fires all at once (they all fit in KV → queue=0 →
  peak batch). At `CONC=256` the *client* is the bottleneck (1713 tok/s, not 9307).
- **Load vs gen are separated:** client timer starts after `/health` 200 (weights ~14s +
  profile+warmup, ~130s cold-start, all excluded); `/metrics` confirms HTTP overhead
  negligible + queue=0, so the timed window is a faithful generation wall-clock.
- `lm-eval` `run_gsm8k_vllm.sh` **cannot** do C7 (offline `LLM`, single-process DP blocked;
  its own `data_parallel_size` = independent replicas, no cross-rank all-to-all).

## Next step — DP lockstep micro-benchmark (agreed; NOT started)

Decision: converting the *whole* DP feature to a benchmark is **low value** (mostly
nano-specific plumbing — schedulers, shm, round-robin, pickle). But **one nugget is
worth extracting**: the **lockstep-under-an-embedded-collective** invariant (the dummy
forward). It's the only non-obvious, fully transferable idea, and it doubles as a
motivating artifact for the verified-control-plane paper thread.

**Build a ~100-line standalone `torchrun` micro-benchmark (no nano-vLLM import):**
- Toy model: `L` layers, each = `all_to_all_single` over `ep_group` + a matmul; a TP×DP mesh.
- Feed replicas **distinct batch sizes incl empty**.
- **(1) Correctness / invariant:** a `--no-dummy` flag → the group **deadlocks**; with the
  dummy forward → completes. This is the crisp failure mode.
- **(2) New numbers — the "lockstep tax":** every replica co-arrives per layer, so the
  **slowest replica per step gates all of them**. Measure tokens/s vs (a) load imbalance
  across replicas and (b) fraction of idle→dummy steps. Quantifies what central-lockstep
  DP costs vs ideal independent DP — a number we don't have and can't guess.
- **Paper hook:** the lockstep rule is a clean control-plane property ("every rank posts
  an identical collective schedule per step"); its violation is a real hang. Sits next to
  the KV-cache bug as evidence the *control plane*, not the kernels, is where subtle
  correctness lives. Slots into the cs336 benchmark template ([[reference-cs336-prior-work]]).

## The DP support, in one screen (for the walkthrough we did)

- **Why it's not clean like C1–C8:** DP is engine plumbing spread across
  `llm_engine`/`model_runner`/`sequence`/`parallel`, not a self-contained block.
- **The constraint:** `ep_group=world` puts a cross-replica all-to-all in *every* forward,
  so replicas must co-arrive at each of 48 MoE layers → can't be independent DDP workers →
  **central orchestration (Architecture A)**: rank 0 drives one synchronized global step.
- **Execution model:** single-controller. `call("run_dp", payload)` broadcasts via shm and
  runs `run_dp` on **all** ranks; each picks `payload[rank//tp_size]`.
- **Pieces:** `llm_engine` N schedulers + round-robin admission + DP step
  ([:75-90](nanovllm-weiz/nanovllm/engine/llm_engine.py#L75-L90)); `model_runner.run_dp`
  ([:304-324](nanovllm-weiz/nanovllm/engine/model_runner.py#L304-L324)) + `run_dummy`
  ([:289-302](nanovllm-weiz/nanovllm/engine/model_runner.py#L289-L302)) + hybrid assert +
  dp-leader group; `sequence` pickles `temperature`; `parallel` adds
  `get_dp_leader_group`/`get_replica_index`/`is_tp_leader`. `scheduler.py` **unchanged**.
- **Can't-hang invariants:** (1) every replica forwards each step (real or dummy);
  (2) exactly the DP leaders `gather_object`; (3) `new_group` creation order identical on
  all ranks. `DP>1` requires `MOE_EP_MODE=hybrid` (allreduce mode → `[T,H]` shape mismatch).
