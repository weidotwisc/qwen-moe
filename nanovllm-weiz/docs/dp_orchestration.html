DP Orchestration

How the data-parallel engine launches one process per GPU, hands tokenized prompts to each replica, and reports sampled tokens back to rank 0 to drive scheduling — a single-controller / SPMD-worker loop.

rank 0 — controller and worker
control plane — shared memory + Events
data plane — NCCL collective

1 · Launch — one OS process per GPU

2 · One global step — hand out work, run, report back

Concrete trace — 2 GPUs (DP=2, TP=1), prompt 1 → replica 0 (+100 tokens), prompt 2 → replica 1 (+50). Both take the run() branch through prefill and the first ~50 decode steps. Once prompt 2 hits 50 tokens, schedulers[1].is_finished() flips → replica 1's slot becomes [] → run_dummy() for ~50 steps while prompt 1 finishes. is_finished() returns true only when both schedulers are done, so the two ranks stop on the same step.
