## Gotchas / hard-won knowledge

- **`enforce_eager=True` is required for the MoE** (data-dependent routing shapes +
  host syncs → not CUDA-graph-capturable). Dense Qwen3 *can* graph. Making MoE
  graph-able (padded/capacity routing) is future work.
- **EP degree = `tensor_parallel_size` (`tp==ep==world`, flat group).** `128 % ep == 0`
  → `ep ∈ {1,2,4,8}`. Run: `CUDA_VISIBLE_DEVICES=0..N TP=N MOE_KERNEL=fused python gsm8k_moe.py`.
- **Same-node parallel runs need distinct `NANOVLLM_DIST_PORT`** (default 2333) or NCCL EADDRINUSE.
- **vLLM on GPFS: add `safetensors_load_strategy=prefetch`** to `--model_args` (underscores, no `--`). Cut vLLM TP8 E2E **602s→251s** (GPFS isn't on vLLM's NFS/Lustre auto-prefetch allowlist). Already in `scripts/vllm/run_gsm8k_vllm.sh`.
- **Don't commit:** `.venv/`, `.venv-vllm/` (gitignored now), `nanovllm-jun/`, `scripts/vllm/results/`. Stage explicitly, never `git add scripts/` (8 GB venv).
- **Security:** `~/.junrc` (world-readable) holds live secrets (GIT_PAT, LLM_API_KEY, LITELLM). **Never reproduce those values.**
- vLLM oracle protocol (lm-eval gsm8k): 5-shot, greedy (temp 0), `max_gen_toks=256`, strict `#### N` + flexible last-number. `gsm8k_moe.py` matches it except temp=0.1 (nano forbids greedy) — hence ±1-question noise.

## Next steps — C7/C8 plan (agreed last session)

**Insight:** C7 = C8 `HybridMoE` @ `tp_size=1`. So port the *general* HybridMoE
(`bootcamp/ex07_tp_ep_hybrid/solution.py` is the template) rather than a separate
C7. The device-mesh machinery (separate `tp_group`/`ep_group`) is already designed
in that C8 solution — reuse the pattern.

Incremental path (each step validated against the 0.8923 oracle):

1. **Port `HybridMoE` into `qwen3_moe.py` as a new mode; run with `tp_group = world`
   (replicated batch = nano's *current* engine, NO engine change).** Phase 0 stripes
   the replicated input across ranks → all-to-all dispatch → local experts →
   all_gather back → replicated output. Validates the dispatch/stripe/gather path in
   nano with zero engine work. (This is "dispatch on replicated input" — the
   *redundant* case the paper contrasts with C6's all_reduce, but it de-risks the block.)
   **← recommended first cut, runnable today on the 8 GPUs.**
2. **Add the device mesh:** construct `tp_group` + `ep_group` in `model_runner`;
   thread `tp_group` into the linears (they must use `dist.get_world_size(group=tp_group)`
   instead of the world — mirror C8's `TPGQA` which takes explicit `tp_size/tp_rank/group`).
   Now `tp < world` is expressible → `tp=1` gives **C7**.
3. **Build the engine-level DP** (the hard part, not in any bootcamp block since they
   test single blocks): partition the batch across `tp_groups`, per-rank scheduling/KV,
   **gather** outputs, and **lockstep stepping** (the MoE all-to-all is a collective —
   every rank must reach each MoE layer together, so ranks can't run as independent
   engines). Strawman: central scheduler partitions one global batch across ranks,
   all run synchronously. Unlocks **true C7 (`tp=1`) and C8 (`tp=4`)**.

Steps 1–2 are bounded block/refactor work; Step 3 is the real engine change —
**scope it in plan mode before coding.**
